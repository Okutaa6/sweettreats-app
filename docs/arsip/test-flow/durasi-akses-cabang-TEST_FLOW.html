Test Flow — Durasi Per-Cabang & Akses Pasien Cross-Cabang

Durasi dokter per-cabang + akses pasien cross-cabang Versi 2026-05-23 Estimasi 40-55 menit 26 test cases
Cara pakai: Klik Pass/Fail tiap test — progress otomatis ke-save di browser (LocalStorage), bisa di-export JSON / print PDF. Test ini menguji UI + Database. Jalankan di LOKAL atau STAGING (copy prod) — jangan langsung di produksi karena membuat & mengubah data nyata. Hanya Section F (Audit Duplikat) yang aman read-only utk dijalankan langsung di prod.
Prasyarat fitur live di environment uji: multi-pasien (raw_contact_id, relasi), Flexible Scheduling (raw_doctor_schedule_exception, kolom duration_minutes di pivot), dan akun login ber-session('raw_branch_id') (Sales cabang) harus sudah berjalan. Test flow ini menguji tambahan di atas: durasi per-cabang + akses pasien cross-cabang.

Bug Reporting Template

Kalau ada test yang fail, laporkan dengan format:

Test ID    : T-X.X
Environment: Lokal / Staging  ·  Browser + versi (utk UI bug: sebut HP/desktop)
Request    : [method + URL + body]
Expected   : [yang seharusnya]
Actual     : [status code + body response]
Cek DB     : [hasil query verifikasi kalau relevan]
Catatan untuk tester:
  1. Jalankan di LOKAL/STAGING, kecuali Section F (audit) yang read-only & aman di prod.
  2. Section B & C mengubah durasi dokter — catat nilai awal sebelum diubah, kembalikan di akhir test (kecuali di staging).
  3. Verifikasi DB: phpMyAdmin atau php artisan tinker (setiap test punya query cek).
  4. Section C BERGANTUNG ke Section B (durasi yg di-set di B dipakai test di C). Jangan dilompati.
  5. Section D butuh 2 akun login: Sales cabang A & Sales cabang B (biasanya logout-login). Test cross-cabang dari perspektif tiap akun.
  6. Kalau ada test fail di Section C, hampir pasti karena cache view — coba php artisan view:clear dan hard-refresh browser (Ctrl+Shift+R).

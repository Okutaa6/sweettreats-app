Test Flow — Reservasi Multi-Pasien

1 nomor → banyak pasien Versi 2026-05-18 Estimasi 45-60 menit 23 test cases
Cara pakai: Klik Pass/Fail tiap test — progress otomatis ke-save di browser (LocalStorage), bisa di-export JSON / print PDF. Ini uji UI + Database (bukan API/token). Jalankan di LOKAL atau STAGING (copy prod) — jangan langsung di produksi karena membuat data reservasi nyata.

Saat tes override perawatan di mobile, pakai dropdown dokter saja; multi-perawatan via override diuji di desktop dulu. Perbaikan (checkbox/chip tap-friendly) menyusul.

Pre-Requisites

1. Jalankan 2 SQL (URUTAN WAJIB!)

phpMyAdmin → DB lokal sweettreats / staging → tab SQL → tempel seluruh isi file (jangan dipotong, ada DELIMITER) berurutan dari database/sql/:

#FileApa yang dilakukan
12026_05_18_contact_anchored_patients.sqlTambah kolom raw_customer.raw_contact_id + relasi + index (idempoten)
22026_05_18_contact_backfill.sqlBuat 1 raw_contact per nomor, isi raw_contact_id data lama, + view v_contact_patient_conflicts
Backup dulu sebelum jalankan (phpMyAdmin → Export). File 2 butuh MariaDB ≥10.0.5 / MySQL ≥8 (REGEXP_REPLACE). Backfill tidak menghapus apa pun & aman dijalankan ulang.

2. Nyalakan & siapkan

LangkahPerintah
Bersihkan cache viewphp artisan view:clear
Nyalakan server lokalphp artisan serve (→ http://127.0.0.1:8000)
Form publikhttp://127.0.0.1:8000/reservasi
Admin (login dulu)menu Reservasi → /rawreservation

3. Data uji yang disiapkan

ButuhCara
Nomor uji BARU (belum ada)mis. 081299900001 — pastikan belum ada: SELECT * FROM raw_customer WHERE phone='081299900001'; (kosong)
Nomor uji LAMA (sudah ada pasien)ambil dari data nyata: SELECT phone, COUNT(*) FROM raw_customer WHERE phone<>'' GROUP BY phone HAVING COUNT(*)>=1 LIMIT 5;
Cabang/dokter yang punya jadwalSELECT * FROM raw_doctor_schedule LIMIT 5; → catat cabang & dokter
Verifikasi DB pakai phpMyAdmin atau php artisan tinker. Setiap test yang relevan sudah ada query-nya. Pakai nomor uji 0812999xxxxx supaya gampang dibersihkan: DELETE FROM raw_cus_reservation WHERE raw_customer_id IN (SELECT id FROM raw_customer WHERE phone LIKE '0812999%'); DELETE FROM raw_customer WHERE phone LIKE '0812999%'; DELETE FROM raw_contact WHERE phone LIKE '0812999%';

Bug Reporting Template

Kalau ada test yang fail, laporkan dengan format:

Test ID    : T-X.X
Environment: Lokal / Staging  ·  Browser + versi (utk UI bug: sebut HP/desktop)
Request    : [method + URL + body]
Expected   : [yang seharusnya]
Actual     : [status code + body response]
Cek DB     : [hasil query verifikasi kalau relevan]
Catatan untuk tester:
  1. Jalankan di LOKAL/STAGING, bukan produksi (test ini membuat reservasi nyata).
  2. Pakai nomor uji 0812999xxxxx → mudah dibersihkan (query cleanup ada di Pre-Requisites).
  3. Verifikasi DB: phpMyAdmin atau php artisan tinker (query ada di tiap test).
  4. Section C (auto-jam) berurutan — slot terpakai bergantung test sebelumnya; refresh data kalau perlu.
  5. Tes Section B/C di desktop dulu; ulangi alur inti (B.2–B.4) di HP untuk cek responsif (kecuali override perawatan — lihat known limitation di atas).

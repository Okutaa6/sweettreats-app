FASE 2 Install dependencies — composer install ▾

Action

Buka hPanel → Advanced → Browser Terminal (atau SSH). Pindah ke folder app & install:

cd {PROJECT_PATH}
composer install --no-dev --optimize-autoloader
Kalau plan Hostinger ini tidak ada Terminal/SSH: install lokal (composer install di komputer kamu), lalu upload seluruh folder vendor/ lewat FileZilla. Lama (~5000 file) tapi sekali aja.

Verifikasi

Jalankan:

{PHP_PATH} {PROJECT_PATH}/artisan --version
❌ Kalau gagal
  • php: command not found → cek path lengkap PHP CLI dari hPanel → PHP Configuration
  • Extension missing → cek php -m (butuh: pdo_mysql, mbstring, openssl, curl, gd)
  • Composer not found → install: curl -sS https://getcomposer.org/installer | php lalu pakai php composer.phar

Action

FASE 6 🔥 BACKFILL DATA 3 TAHUN — langkah paling penting (~30–60 menit) ▾
⚠️ Jangan skip atau persingkat range tanggal. Tujuan deploy ini = bawa 3 tahun riwayat transaksi. Kalau dipersingkat, laporan jadi pincang.

6A. Backfill master data (cepat, ~1 menit)

{PHP_PATH} {PROJECT_PATH}/artisan omnicare:sync --endpoint=doctor
{PHP_PATH} {PROJECT_PATH}/artisan omnicare:sync --endpoint=polyclinic
{PHP_PATH} {PROJECT_PATH}/artisan omnicare:sync --endpoint=patient

Verifikasi 6A — di phpMyAdmin SQL:

SELECT COUNT(*) FROM omnicare_doctor;
SELECT COUNT(*) FROM omnicare_polyclinic;
SELECT COUNT(*) FROM omnicare_patient;
SELECT COUNT(*) FROM omnicare_location;

6B. Backfill sales 3 tahun (LAMA — ~30 menit)

Tanggal otomatis: hari ini = → 3 tahun ke belakang = .

{PHP_PATH} {PROJECT_PATH}/artisan omnicare:sync --endpoint=sales --start={START_YMD} --end={END_YMD}

Setelah itu (~30 menit lagi):

{PHP_PATH} {PROJECT_PATH}/artisan omnicare:sync --endpoint=product --start={START_YMD} --end={END_YMD}
Jangan tutup terminal! Pakai screen / tmux kalau SSH: 
screen -S backfill-sales
# jalankan command di atas
# Ctrl+A lalu D untuk detach
# balik: screen -r backfill-sales

Verifikasi 6B

SELECT
  MIN(trx_date) sejak,
  MAX(trx_date) sampai,
  COUNT(*) baris,
  COUNT(DISTINCT trx_id) trx_unique
FROM omnicare_sales_detail;

Per cabang:

SELECT place_id, COUNT(*) baris, COUNT(DISTINCT trx_date) hari, MAX(trx_date) terakhir
FROM omnicare_sales_detail
GROUP BY place_id;

Sanity check — banding dgn audit Bintaro Maret 2026

SELECT SUM(net_sell_price) total
FROM omnicare_sales_detail
WHERE place_id = 29957
  AND trx_date BETWEEN '2026-03-01' AND '2026-03-31'
  AND item_type <> 'V'
  AND LOWER(item_name) NOT LIKE 'service charge%';
❌ Kalau putus di tengah

Aman. Sync idempotent (INSERT ON DUPLICATE KEY UPDATE per trx_id). Jalankan ulang command yang sama — akan skip yang sudah masuk, lanjut yang belum.

SELECT * FROM omnicare_sync_log ORDER BY started_at DESC LIMIT 5;

Verifikasi esok hari (setelah jam 03:30)

SELECT
  endpoint, status, started_at, finished_at, rows_synced
FROM omnicare_sync_log
WHERE started_at >= CURDATE()
ORDER BY started_at;
SELECT MAX(trx_date) FROM omnicare_sales_detail;
❌ Kalau cron tidak jalan
  • Cek path PHP di cron command — pakai value di Settings di atas, atau cek which php
  • Di hPanel Cron Jobs → Send Output to Email → cek error
  • Test manual: jalankan command yang sama di Terminal, lihat output

🚨 Rollback (kalau ada masalah serius pasca-deploy)

Backup DB sudah diambil di Fase 0. Untuk rollback:

  1. Disable cron: hPanel → Cron Jobs → delete entry
  2. Restore DB: phpMyAdmin → Import → upload backup .sql
  3. Hapus file Omnicare atau restore folder pre-deploy
  4. Hubungi Ekky untuk troubleshoot sebelum coba lagi

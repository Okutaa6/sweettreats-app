🦷 Cara Kerja Git — biar ngoding bareng ga ribet

Lupain kirim ZIP & upload FileZilla buat ngoding. Mulai sekarang semua lewat 1 tempat pusat. Baca sekali, 10 menit, langsung bisa jalan. Santai — udah ada pengaman biar lu ga mungkin ngerusak.

🎯
Inti banget: cabang main = kode yang dipakai klinik beneran. Lu ga pernah ngoding langsung di main — selalu di cabang sendiri, terus minta gabung lewat Pull Request.

① Sekali doang: setup di laptop lu

1
Install Git
Download di git-scm.com. Cek udah masuk:
git --version
2
Kenalin diri ke Git (sekali)
git config --global user.name "Nama Lu"
git config --global user.email "email@lu.com"
3
Ambil kodenya (clone) — sekali, langsung dapet semua
git clone git@github.com:Ekkyrb/sweettreats-app.git
cd sweettreats-app
4
Siapin biar jalan di lokal
composer install
# minta file .env ke tim lead, taruh di root project, lalu:
php artisan key:generate
📌 .env & vendor/ ga ikut Git — itu wajar & emang sengaja. Minta .env ke tim lead.

1
Ambil versi terbaru dulu WAJIB pertama
Biar lu kerja di atas kode paling baru, ga nabrak punya temen.
git checkout main
git pull origin main
2
Bikin cabang sendiri buat tugas ini
1 tugas = 1 cabang. Nama jelas: fitur/... atau fix/...
git checkout -b fitur/laporan-bulanan
3
Ngoding biasa, terus "simpan checkpoint" (commit)
Commit tiap selesai 1 bagian — jangan numpuk seharian baru commit.
git add .
git commit -m "tambah tampilan laporan bulanan"
4
Kirim cabang lu ke GitHub
git push origin fitur/laporan-bulanan
5
Buka Pull Request (PR) di browser
Buka repo di GitHub → muncul tombol hijau “Compare & pull request” → isi judul + 1-2 kalimat penjelasan → Create pull request.
💬 PR itu artinya: “Permisi, kerjaan gua udah siap, tolong dicek sebelum digabung ke main.”
6
Tunggu di-review & di-merge tim lead
Tim lead lihat perubahan lu, komentar kalau perlu, lalu klik Merge. Kelar — kerjaan lu masuk main. Upload ke server (prod) diurus tim lead/Reza, bukan lu.

④ Tenang — lu ga akan bisa ngerusak 🛡️

Udah ada pengaman otomatis:

🔒
main dikunci. Walau lu coba push langsung ke main, GitHub bakal nolak. Harus lewat PR + disetujui tim lead. Jadi mustahil ngerusak yang dipakai klinik.
🔒
Force-push & hapus main diblokir. Ga bisa "nimpa paksa" history orang.
🧯
Semua kesimpen di history. Salah? Tinggal balikin. Beda sama ZIP yang sekali ketimpa ya ilang.
🔑
.env & secret aman. Ke-ignore + ada scanner yang nolak kalau ada yang ke-commit ga sengaja.

Intinya: selama lu ga pakai --force dan ga ngedit server langsung, Git itu jaring pengaman — bukan jebakan. Berani aja eksperimen di branch lu.

⑤ Kalau kena masalah

SituasiLakuin
Muncul tulisan “CONFLICT”Kerjaan lu & temen nyentuh baris sama. Jangan asal hapus. Tanya tim lead — diberesin bareng (sebentar kok).
Push “rejected”Ada update baru. git pull origin <branch-lu> dulu, baru git push lagi.
Udah ngoding tapi lupa bikin branchJangan commit ke main. Tanya tim lead (biasanya git stash → bikin branch → git stash pop).
Takut salah / bingungSTOP, tanya. 99% kesalahan Git bisa dibalikin selama belum --force.

⑦ FAQ

Branch itu apa?
Kayak "ruang kerja kopian" buat lu otak-atik tanpa ganggu yang asli (main). Kalau udah beres & disetujui, baru digabung.
Kenapa ga langsung edit main biar cepet?
main = yang dipakai klinik beneran. Salah dikit = klinik error. Lagian GitHub udah ngunci main, jadi emang ga bisa.
Masih boleh pakai FileZilla?
Buat lihat file server: boleh. Buat ngedit/upload kode: TIDAK. Semua kode lewat Git.
Kerjaan gua bisa ilang ga?
Hampir mustahil (selama ga --force). Semua kesimpen di history. Git lebih aman dari ZIP.
Commit itu beda sama push?
Commit = simpan checkpoint di laptop lu. Push = kirim checkpoint itu ke GitHub. Commit dulu (boleh banyak), baru push.

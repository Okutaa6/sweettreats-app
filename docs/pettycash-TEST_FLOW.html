Test Flow — Petty Cash

Buku kas kecil (imprest) Versi 2026-05-20 Estimasi 30-45 menit 25 test cases
Cara pakai: Klik Pass/Fail tiap test — progress otomatis ke-save di browser (LocalStorage), bisa di-export JSON / print PDF. Ini uji UI + Database halaman /pettycash. Jalankan di LOKAL atau STAGING (copy prod) — jangan langsung di produksi karena membuat data transaksi nyata.
Konsep imprest (dana tetap): saldo dipatok di float_amount (default Rp 1.500.000). Setiap top up mengisi saldo kembali ke nilai itu. Saldo berjalan tidak disimpan permanen — dihitung saat render dari opening_balance + Σ(cash_in − cash_out). Carry-forward: opening bulan baru = closing bulan lalu.

Pre-Requisites

1. Jalankan 1 SQL Migration

phpMyAdmin → DB lokal sweettreats / staging → tab SQL → tempel seluruh isi file berurutan dari database/sql/:

#FileApa yang dilakukan
12026_05_20_petty_cash.sqlBikin 2 tabel (petty_cash_periods, petty_cash_transactions) + ALTER auto-upgrade kolom created_by varchar(36) + seed periode pertama dengan opening_balance = 0
Backup dulu sebelum jalankan (phpMyAdmin → Export). File ini idempoten: aman dijalankan berapa kali pun. Mencakup CREATE IF NOT EXISTS + ALTER MODIFY + UPDATE kondisional (reset opening 0 hanya untuk periode tanpa transaksi).

2. Nyalakan & siapkan

LangkahPerintah
Bersihkan cache view + routephp artisan view:clear && php artisan route:clear
Nyalakan server lokalphp artisan serve (→ http://127.0.0.1:8000)
Halaman Petty Cash (login dulu)http://127.0.0.1:8000/pettycash
Tambah menu di sidebar (opsional)via SQL group_access atau Setting → Akses → Save (path pettycash)

3. Data uji yang disiapkan

ButuhCara
User login (catat UUID-nya)SELECT id, name FROM users LIMIT 5; → catat id (UUID) — akan muncul di kolom created_by
Periode awal seharusnya munculSELECT * FROM petty_cash_periods; → 1 baris dengan opening_balance=0, float_amount=1500000
Ledger awal kosongSELECT COUNT(*) FROM petty_cash_transactions; → 0
Cleanup setelah test: DELETE FROM petty_cash_transactions; DELETE FROM petty_cash_periods; lalu re-run migration. Hati-hati: ini hapus SEMUA data — pakai filter WHERE description LIKE 'TEST%' kalau prod.

Catatan untuk tester:
  1. Jalankan di LOKAL/STAGING, bukan produksi (test ini membuat transaksi nyata).
  2. Pakai keterangan TEST - xxx di setiap input → mudah filter & cleanup nanti.
  3. Verifikasi DB: phpMyAdmin atau php artisan tinker (query ada di tiap test).
  4. Section D (pengeluaran) bergantung sama Section C (top up dulu supaya saldo ada).
